
# 4. Hasil Pengujian (Test Execution Report)

Berdasarkan eksekusi pengujian yang telah dilakukan terhadap aplikasi Sistem Pengaduan Masyarakat, berikut adalah hasil akhir dari skenario pengujian yang direncanakan:

### 4.1 Hasil Pengujian Black Box
| ID Test | Skenario Pengujian | Status Akhir | Keterangan / Catatan |
|---|---|---|---|
| **BB-01** | Mengirim pengaduan dengan data valid | **PASS** | Sistem memunculkan notifikasi sukses dengan benar. |
| **BB-02** | Mengirim pengaduan dengan isi laporan kosong | **FAIL** | **Bug:** Sistem tetap memproses laporan masuk. Akan dilaporkan via GitHub Issues. |
| **BB-03** | Admin memfilter Laporan Bulanan | **PASS** | Data terfilter dengan benar sesuai bulan dan tahun. |
| **BB-04** | Admin memberi tanggapan kosong | **PASS** | Sistem menolak input dan memunculkan error validasi. |

### 4.2 Hasil Pengujian White Box
Berikut adalah laporan eksekusi pengujian internal yang dilakukan secara nyata terhadap kode program Sistem Informasi Pengaduan Masyarakat di lingkungan *localhost* (XAMPP):

| ID Test | Model Pengujian | Deskripsi Pengujian Internal | Status Akhir | Keterangan / Catatan |
|---|---|---|---|---|
| **WB-01** | Desk Checking | Pemeriksaan logika variabel perubahan status laporan pengaduan. | **PASS** | Variabel berubah dari '0', '1', hingga '2' (Selesai) secara konsisten di memori sistem. |
| **WB-02** | Code Walkthrough | Peninjauan kode keamanan input form terhadap serangan injeksi SQL. | **PASS** | Seluruh query database untuk modul pengaduan masyarakat telah dilindungi fungsi sanitasi input dengan benar. |
| **WB-03** | Formal Inspections | Inspeksi format validasi data kosong (*Empty Field*) pada form input laporan. | **PASS** | Validasi memicu pesan error modal "Empty Field" secara tepat apabila input masyarakat kosong. |
| **WB-04** | Control Flow Testing | Pengujian percabangan logika arah *dashboard login* berdasarkan tingkatan *role*. | **PASS** | Jalur pengalihan hak akses Admin dan Masyarakat berfungsi 100% tanpa ada salah arah tujuan. |
| **WB-05** | Basic Path Testing | Eksekusi seluruh jalur keputusan alur laporan pengaduan berdasarkan *flowchart*. | **PASS** | Semua kemungkinan kombinasi alur status pengaduan lulus uji coba dengan nilai kompleksitas yang aman. |
| **WB-06** | Data Flow Testing | Pelacakan siklus hidup pengiriman variabel teks laporan ke dalam database MySQL. | **PASS** | Data terkirim secara utuh dari interface menuju baris tabel database phpMyAdmin secara *real-time*. |
| **WB-07** | Loop Testing | Pengujian perulangan penayangan daftar laporan pengaduan pada akun halaman masyarakat. | **PASS** | *Looping foreach* berhasil menampilkan 50 data laporan pengaduan sekaligus secara rapi tanpa terpotong. |
