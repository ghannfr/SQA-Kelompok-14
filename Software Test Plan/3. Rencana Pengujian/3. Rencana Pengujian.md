### 3.2 Skenario Pengujian White Box
Bagian ini menguraikan skenario pengujian internal kode program (*source code*) berdasarkan 7 model pengujian White Box Testing yang mengacu pada standar SQA pertemuan 10:

| ID Test | Model Pengujian | Deskripsi Pengujian Internal | Expected Result (Ekspektasi) |
|---|---|---|---|
| **WB-01** | Desk Checking | Memeriksa perubahan nilai variabel `$status_laporan` secara manual dari nilai awal '0' (Pending) menjadi '1' (Proses) saat Admin menanggapi pengaduan. | Variabel berubah secara logis tanpa menyebabkan nilai *null* atau *error data type*. |
| **WB-02** | Code Walkthrough | Meninjau baris kode penanganan *session login* secara bersama-sama untuk memastikan penggunaan fungsi `mysqli_real_escape_string()` guna mencegah celah *SQL Injection*. | Logika sanitasi input aman dan dipahami oleh seluruh anggota tim pengembang. |
| **WB-03** | Formal Inspections | Memeriksa ketepatan format pesan validasi data kosong (*Empty Field*) ketika form pengaduan dikirim tanpa mengisi kolom NIK atau isi laporan. | Sistem memicu fungsi alert/modal "Semua kolom wajib diisi!" dengan format tampilan yang tepat. |
| **WB-04** | Control Flow Testing | Menguji jalur kendali percabangan logika fungsi `loginAuth()`. Jika kondisi variabel `$role == 'admin'`, arahkan ke `/admin`, dan jika `$role == 'masyarakat'`, arahkan ke `/user`. | Alur logika *control flow* mengarahkan *session user* ke halaman dasbor yang tepat tanpa terjebak *infinite loop*. |
| **WB-05** | Basic Path Testing | Mengidentifikasi semua jalur eksekusi independen alur peninjauan laporan pengaduan (Masuk -> Verifikasi -> Tanggapan -> Selesai) menggunakan perhitungan metrik *Cyclomatic Complexity*. | Seluruh jalur keputusan logika (`if-else`) berhasil dieksekusi minimal satu kali tanpa ada jalur yang terlewat. |
| **WB-06** | Data Flow Testing | Melacak aliran data dari variabel `$isi_laporan` dan `$foto_bukti` sejak diinput oleh masyarakat di interface, diproses fungsi simpan, hingga masuk ke dalam tabel `tbl_pengaduan`. | Aliran variabel terkarakterisasi dengan aman dan tersimpan ke database MySQL tanpa ada kehilangan data (*data loss*). |
| **WB-07** | Loop Testing | Menguji kinerja perulangan `while` atau `foreach` pada fungsi tabel riwayat pengaduan masyarakat ketika data yang ditarik berjumlah 0, 1, hingga banyak baris data. | Proses *looping* data laporan berjalan lancar dan berhenti secara tepat waktu tanpa mengalami kendala memori (*trap loop*). |

### 3.3 Skenario Pengujian Grey Box
| ID Test | Area Pengujian | Skenario Pengujian | Expected Result (Ekspektasi) |
|---|---|---|---|
| **GB-01** | Keamanan URL | Akses URL `/admin/laporan` menggunakan akun masyarakat | Sistem memblokir akses dan mengembalikan ke halaman 403 Forbidden |
| **GB-02** | Sinkronisasi DB | Admin mengubah status laporan menjadi "Selesai" di UI | Kolom `status` pada tabel `tbl_pengaduan` di database berubah secara real-time |
